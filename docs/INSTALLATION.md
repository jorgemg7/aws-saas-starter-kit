# Installation Guide

This guide explains how to deploy the AWS SaaS Starter Kit from scratch.

The deployment uses:

- AWS
- Terraform
- Amazon Cognito
- API Gateway
- AWS Lambda
- DynamoDB
- Amazon S3
- CloudFront
- GitHub Actions
- Next.js

---

## 1. Requirements

Before starting, install:

- Git
- Node.js 24+
- npm
- AWS CLI
- Terraform 1.13+
- An AWS account

Verify the tools:

```bash
git --version
node --version
npm --version
aws --version
terraform version
2. Configure AWS CLI

Configure credentials for the AWS account that will host the application:

aws configure

Verify access:

aws sts get-caller-identity

The command should return the AWS account and IAM identity being used.

Make sure the identity has enough permissions to create the resources defined by Terraform.

3. Clone the repository

Clone the project and enter the repository:

git clone <YOUR_REPOSITORY_URL>
cd aws-saas-starter-kit
4. Create the Terraform state bucket

The project uses an S3 backend with Terraform locking.

Create a dedicated S3 bucket in your AWS account for Terraform state.

Example:

aws s3api create-bucket \
  --bucket YOUR_UNIQUE_TERRAFORM_STATE_BUCKET \
  --region eu-west-1 \
  --create-bucket-configuration LocationConstraint=eu-west-1

The bucket name must be globally unique.

Do not use the bucket name from the original development environment.

5. Configure Terraform backend

Copy the example backend configuration:

cp terraform/backend.hcl.example terraform/backend.hcl

Edit the file:

nano terraform/backend.hcl

Set your bucket name:

bucket = "YOUR_TERRAFORM_STATE_BUCKET"
key    = "terraform.tfstate"
region = "eu-west-1"

encrypt      = true
use_lockfile = true

terraform/backend.hcl is environment-specific and should not be committed.

6. Initialize Terraform

Enter the Terraform directory:

cd terraform

Initialize Terraform using the backend configuration:

terraform init -backend-config=backend.hcl

Terraform will configure the S3 remote state backend and download the required providers.

7. Validate Terraform

Run:

terraform fmt -check -recursive
terraform validate

The configuration should validate successfully.

The AWS provider may display a deprecation warning for the DynamoDB hash_key argument. This warning does not prevent validation.

8. Review the Terraform plan

Run:

terraform plan -input=false

Review the resources before applying them.

The infrastructure includes:

S3
CloudFront
Cognito
API Gateway
Lambda
DynamoDB
IAM
CloudWatch resources
9. Deploy the infrastructure

When the plan has been reviewed:

terraform apply -input=false

Confirm the deployment when Terraform asks for confirmation.

10. Get Terraform outputs

After deployment:

terraform output

The important outputs include:

backend_api_url
cloudfront_distribution_id
cloudfront_domain_name
cognito_client_id
cognito_user_pool_id
frontend_bucket_name
invitations_table_name
organizations_table_name
users_table_name

These values are generated by your AWS environment.

11. Configure the frontend

Return to the project root:

cd ..

Create the local frontend environment file:

cp web/.env.example web/.env.local

Edit it:

nano web/.env.local

Set the values from terraform output:

NEXT_PUBLIC_API_URL=
NEXT_PUBLIC_AWS_REGION=eu-west-1
NEXT_PUBLIC_COGNITO_USER_POOL_ID=
NEXT_PUBLIC_COGNITO_CLIENT_ID=

For example:

NEXT_PUBLIC_API_URL=https://YOUR_API_ID.execute-api.eu-west-1.amazonaws.com
NEXT_PUBLIC_AWS_REGION=eu-west-1
NEXT_PUBLIC_COGNITO_USER_POOL_ID=eu-west-1_xxxxx
NEXT_PUBLIC_COGNITO_CLIENT_ID=xxxxxxxx

Never commit web/.env.local.

12. Install frontend dependencies
cd web
npm ci

Run linting:

npm run lint

Build the frontend:

npm run build

The static export will be generated in:

web/out/
13. Test the backend

From the project root:

cd backend
npm ci

Run the test suite:

npm test

Build the backend:

npm run build
14. Manual frontend deployment

The frontend can be uploaded directly to the Terraform-created S3 bucket.

From the project root:

aws s3 sync \
  web/out \
  s3://YOUR_FRONTEND_BUCKET \
  --delete

Replace YOUR_FRONTEND_BUCKET with:

terraform -chdir=terraform output -raw frontend_bucket_name

After uploading, invalidate the CloudFront cache:

aws cloudfront create-invalidation \
  --distribution-id "$(terraform -chdir=terraform output -raw cloudfront_distribution_id)" \
  --paths "/*"

The CloudFront domain can be obtained with:

terraform -chdir=terraform output -raw cloudfront_domain_name
15. GitHub Actions deployment

The repository includes a GitHub Actions deployment workflow.

The workflow runs when changes are pushed to main.

The workflow:

Installs backend dependencies
Runs backend tests
Builds the backend
Installs frontend dependencies
Lints the frontend
Builds the frontend
Checks Terraform formatting
Validates Terraform
Creates a Terraform plan
Applies the Terraform plan
Uploads the frontend to S3
Invalidates CloudFront
16. GitHub Actions secrets

Configure these repository secrets:

AWS_DEPLOY_ROLE_ARN
NEXT_PUBLIC_API_URL
NEXT_PUBLIC_AWS_REGION
NEXT_PUBLIC_COGNITO_USER_POOL_ID
NEXT_PUBLIC_COGNITO_CLIENT_ID
FRONTEND_BUCKET_NAME
CLOUDFRONT_DISTRIBUTION_ID

The values can be obtained from Terraform outputs.

For example:

terraform -chdir=terraform output -raw backend_api_url
terraform -chdir=terraform output -raw cognito_user_pool_id
terraform -chdir=terraform output -raw cognito_client_id
terraform -chdir=terraform output -raw frontend_bucket_name
terraform -chdir=terraform output -raw cloudfront_distribution_id
17. AWS credentials for GitHub Actions

The deployment workflow uses:

GitHub Actions
      ↓
OIDC
      ↓
AWS IAM Role

The workflow expects the ARN of this IAM role in:

AWS_DEPLOY_ROLE_ARN

Do not store long-lived AWS access keys in GitHub repository secrets.

18. Verify the deployment

After deployment, open the CloudFront domain:

terraform -chdir=terraform output -raw cloudfront_domain_name

Verify:

The frontend loads
User registration works
User login works
Cognito authentication works
A new user receives an organization
Organization members can be listed
Authorized users can invite members
Invitations can be accepted
Member roles can be updated
Unauthorized operations are rejected
19. Environment files

The repository includes example environment files:

backend/.env.example
web/.env.example
terraform/backend.hcl.example

These are templates.

Do not commit:

web/.env.local
terraform/backend.hcl
terraform.tfvars
*.tfstate
*.tfstate.*
20. Troubleshooting
Terraform cannot initialize the backend

Verify:

The S3 bucket exists
The bucket name is correct
The AWS region is correct
Your AWS credentials have access to the bucket

Then run:

terraform init -reconfigure -backend-config=backend.hcl
Frontend build fails

Check:

cat web/.env.local

Make sure all required NEXT_PUBLIC_* variables are populated.

Then run:

npm ci
npm run lint
npm run build
Backend tests fail

Run:

cd backend
npm ci
npm test
CloudFront shows an old version

Create a new invalidation:

aws cloudfront create-invalidation \
  --distribution-id "$(terraform -chdir=terraform output -raw cloudfront_distribution_id)" \
  --paths "/*"
21. Cleanup

To remove the infrastructure created by Terraform:

cd terraform
terraform destroy

Review the resources carefully before confirming.

The Terraform state bucket is separate from the application infrastructure and may need to be removed manually.

23. Production considerations

Before using the starter kit for a production SaaS application, review:

AWS IAM permissions
Cognito configuration
Domain configuration
CloudFront configuration
API security
DynamoDB access patterns
Monitoring and alerting
Logging
Backup and recovery
Cost controls
Environment separation
Application-specific security requirements

This starter kit provides the technical foundation; each SaaS application should be reviewed according to its own production and security requirements.
